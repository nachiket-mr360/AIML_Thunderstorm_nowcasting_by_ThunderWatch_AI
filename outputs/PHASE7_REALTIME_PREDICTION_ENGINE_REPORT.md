# Phase 7 -- Real-time prediction engine report

Generated by `ml/verify_prediction_engine_phase7.py` (independent verification run 2026-09-15).

## 1. Scope

Phase 7 turns the locked Phase 6 model into one production step that can be run live:

```
latest available atmospheric hour t  ->  the same 28 causal Phase 4 features
    ->  probability that the VOTV station reports a thunderstorm in clock hour t + 1
    ->  yes/no alert by comparing that probability with the locked threshold
```

Phase 7 **does not** train, retrain, recalibrate, re-tune or replace anything. The estimator, the 28
features and their order, and the decision threshold are read out of
`models/thunderstorm_nowcast_1h.joblib` exactly as Phase 6 wrote them. The feature mathematics is not
reimplemented: the engine imports `dataset/feature_engineering_phase4.py` by file path and calls its
`add_features()` on the live window, so every column is produced by the same code that produced the
training table.

No Phase 1-6 dataset, model artifact or evaluation output is written, moved or modified, and `app.py`,
the templates and the static frontend are untouched.

| item | value |
| --- | --- |
| model | `models/thunderstorm_nowcast_1h.joblib` (`sklearn.ensemble.RandomForestClassifier`) |
| features | 28 causal features at hour t, Phase 4 order |
| target | `target_1h` -- genuine VOTV thunderstorm observation at t + 1 h |
| locked threshold | `0.0775` (unchanged from Phase 6) |
| lead time | 1 hour |
| live source | Open-Meteo forecast endpoint (`https://api.open-meteo.com/v1/forecast`), 7 hourly variables, `past_days=3`, `forecast_days=1`, UTC |

## 2. Temporal semantics (read before reading the numbers)

The model is a 1-hour nowcast, so the feature hour and the predicted hour are different hours:

* **feature hour t** -- the latest hour for which all seven atmospheric inputs are available and
  complete. All 28 features are functions of hours `<= t` only.
* **predicted hour t + 1** -- the clock hour whose VOTV thunderstorm observation the probability
  refers to. It is exactly one hour after t, and it is still in the future at prediction time.

The engine therefore never reports an observed outcome for the predicted hour: that observation does
not exist yet. Phase 6's measured skill for this exact model/threshold pair is reported alongside the
live score instead, so an alert is never presented as a confirmed thunderstorm.

Hours after the reference instant are discarded rather than used, and this is measured, not asserted:
injecting 48 deliberately corrupted future hours into a window leaves the feature vector and the
probability unchanged (max absolute difference `2.665e-15` for the engine's own truncation check).

## 5. Failure policy

No atmospheric value is ever invented, imputed, defaulted or carried forward. If the provider is
unreachable, returns unexpected units, omits a variable, returns no contiguous fully-populated run of
at least `MIN_PRECEDING_HOURS` (6) hours, leaves the data staler than the caller's freshness limit, or
if any feature comes out NaN/inf, the engine raises `ThunderstormNowcastError` with a machine-readable
`code` and returns no probability.

One behaviour is a deliberate choice rather than a failure: if the newest hour at or before the
reference instant is incomplete or there is a gap, the engine does **not** fill the hole. It steps back
to the newest complete hour, continues the hourly sequence, and reports that it did so in
`selection.trailing_hours_skipped` together with the resulting `temporal_semantics.data_age_hours`. If
the newest complete hour is further back than the freshness limit, the run fails with `stale_data`
rather than presenting an old hour as current.

Typed failure codes exercised by the verifier: `no_recent_hours`, `insufficient_recent_history`,
`stale_data`, `frame_missing_variables`, `frame_duplicate_timestamps`, `frame_not_a_dataframe`,
`frame_missing_timestamp`, `unexpected_units`, `upstream_unreachable`.

## 6. Scientific interpretation and limits

Station-based thunderstorm nowcast prototype trained from VOTV aerodrome METAR present-weather
observations paired with Open-Meteo archive/model-derived atmospheric features at a single grid cell
about 2 km from the station. The output is a model probability that the VOTV station reports a
thunderstorm in a future clock hour, combined with a decision threshold to give a yes/no alert. It is
NOT a nationwide, radar-based, satellite-based, lightning-based or NWP-based thunderstorm forecast, it
is not an IMD operational product, and a probability is not physical certainty about a thunderstorm.
High accuracy figures are achievable by predicting the majority class and are not evidence of skill;
the meaningful figures are recall, precision, F1, PR-AUC and ROC-AUC relative to the reported base rate.

Explicitly:

* The probability is **not a confidence** and not a calibrated frequency of thunderstorms. The forest was
  trained with `class_weight="balanced"`, which shifts scores towards the rare class on purpose, so the
  absolute value is close to meaningless; only the ordering and the locked threshold were validated.
* A probability is **not** physical certainty, and an alert is a **screening signal**, not an observation.
* The measured false-alarm burden is reported with every alert: at recall `0.6040` and precision
  `0.1332`, most alerts are not followed by a thunderstorm (about 6.5 false alarms per hit on the test
  split). Any operational use must plan for that.
* The seven inputs are a model-derived provider grid cell, **not** the VOTV aerodrome ground
  observation, and they are not presented as one.
* **Domain shift:** Phase 6 trained on the Open-Meteo archive endpoint; this engine reads the Open-Meteo
  forecast endpoint, whose latest hours are model-derived. The two products are not guaranteed to be
  distributionally identical, so a live score carries an additional, unquantified caveat.
* The live grid cell is ~2 km from the aerodrome, and labels are aerodrome point observations: a storm
  the station did not report is not a positive label.
* This is not an operational IMD-level forecast product and uses no radar, satellite, lightning or NWP
  fields.
